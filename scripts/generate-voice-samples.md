# Recreate the bundled Kokoro voice previews

The six `assets/voice-samples/*.m4a` files are synthetic Kokoro-82M v1.0 speech, **not recordings**. Their common input is exactly `This is how phi reads replies aloud.`; the voice IDs are `af_heart`, `af_bella`, `af_sarah`, `am_fenrir`, `am_michael`, and `am_puck`. Use the Kokoro-82M Apache-2.0 model and voice packs fetched by the app, not a different speech provider. The generated WAVs are 24 kHz mono; `afinfo` on the current M4A clips reports AAC, 24 kHz mono, roughly 44–48 kb/s actual bit rate (nominal 48 kb/s).

1. Build and install the native iOS app (`npm ci && npx expo run:ios`); Expo Go cannot run the Kokoro native module. On a supported Simulator, launch the installed app with `xcrun simctl launch --terminate-running-process booted com.example.phiremote -phiTtsSelfTest 1 -phiTtsPlay 0 -phiTtsUnits cpu`. Replace the bundle ID if you set `PHI_REMOTE_BUNDLE_ID`. On a physical test device, set the same launch arguments in Xcode's scheme instead. The self-test in `src/services/natural-voice-self-test.ts` downloads the model if needed, then calls `writeWav([SAMPLE_SENTENCE], { voice: v.id }, ...)` for each entry in `NATURAL_VOICES`. Check the `[tts-selftest] done` log and `tts-selftest.json` for errors before using the output. Model download requires network connectivity.
2. Find the Simulator WAVs under `$(xcrun simctl get_app_container booted com.example.phiremote data)/Documents/tts-selftest/sample-<voice>.wav` (or export that Documents folder from the physical device's app container). Check one with `afinfo`: one channel, 24000 Hz. Do not substitute the `reply-<voice>.wav` files; those use a longer test paragraph.
3. In a scratch directory, for each of the six voice IDs, convert with `afconvert -f m4af -d aac -b 48000 in.wav out.m4a`, where `in.wav` is `sample-<voice>.wav` and `out.m4a` is `<voice>.m4a`. Check each output with `afinfo` for mono/24 kHz AAC and listen to confirm the sentence and speaker before replacing `assets/voice-samples/<voice>.m4a`. Encoder version can change output bytes; the format and generation recipe are the reproducibility contract.

See [asset provenance](../docs/ASSET-PROVENANCE.md) and the Kokoro model/voice attribution in [third-party notices](../THIRD_PARTY_NOTICES.md).
